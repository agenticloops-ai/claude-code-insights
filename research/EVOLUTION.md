# Claude Code: Evolution of an Agent

> Black-box study of how `@anthropic-ai/claude-code` changed across **256 captured releases** between **2025-03-10 (`0.2.36`)** and **2026-04-30 (`2.1.126`)**.
> All claims cite a specific version + date + the diff file under `versions/<date>_<version>/`. Underlying data: `research/data/*.csv` and `research/data/milestones.json`, generated by `scripts/mine-evolution.py`.

## Reading guide

The evolution falls into **four eras**:

| Era | Versions | Calendar | Theme |
|---|---|---|---|
| **CLI tool** | `0.2.36` → `0.2.93` | Mar–Apr 2025 | Bash/Read/Replace primitives, snake_case, lowercase tool names |
| **Stable agent** | `1.0.0` → `1.0.126` | May–Sep 2025 | PascalCase rename, plan mode, the modern tool palette settles |
| **Plugin platform** | `2.0.0` → `2.0.71` | Sep–Dec 2025 | Sub-agents, plugin/marketplace surface, Sonnet 4.5 + Haiku 4.5 |
| **Deferred / agentic** | `2.1.0` → `2.1.126` | Jan–Apr 2026 | ToolSearch + lazy schemas, Skills system, scheduled / cloud routines, server-fetched MCP, typed memory, Opus 4.7 |

Five throughlines the data makes obvious:

1. **The pendulum**: tools get added inline → moved to deferred via `ToolSearch` → some snap back to inline. The schema prompt can balloon from 1 KB to 30 KB and back inside a month.
2. **MCP staged for ~2 months before activation**: server tool *names* appeared in the prompt at `2.1.73` (Mar 11), but `mcp_tool_count_deferred` stayed `0` until `2.1.110` (Apr 15) when it jumped 0 → 89 in a single release.
3. **Skills are a 2026 invention**: the `Skill` tool itself shipped at `2.0.20` (Oct 16, 2025), but the actual `<system-reminder>`-driven skill catalog only surfaces in captures from `2.1.23` (Jan 29, 2026) onward.
4. **The 2.1.53 system-prompt rewrite** (Feb 24, 2026) replaced the "interactive CLI tool" framing with "interactive agent", restructured every section, and introduced explicit `# System` and `# Executing actions with care` blocks — the modern voice of Claude Code.
5. **Sandbox warning**: every `mcp__claude_ai_*` and `mcp__plugin_*` name visible in `versions/<v>/raw/` was a server-side enumeration of the auth account's connectors, leaked via the deferred-tools list, not a real Claude Code change. The repo now auto-scrubs them in `scripts/run-scenario.sh`. Don't read meaning into those entries.

### The deferred-tool pendulum

The clearest concept-level transition. Before `2.1.14` every tool's full schema was in the system prompt on every request. From `2.1.14` onward, tools could be **deferred** — their names appear in the user-message context (under `<available-deferred-tools>`, then `<system-reminder>` after `2.1.110`) and the model loads schemas on demand by calling `ToolSearch`.

| Phase | Versions | What happened |
|---|---|---|
| **Always inline** | `0.2.36` → `2.1.13` | `ToolSearch` doesn't exist; every tool schema in the system prompt. |
| **Mixed** | `2.1.14` → `2.1.68` | `ToolSearch` exists; only a few tools deferred (e.g. CronCreate/Delete/List, RemoteTrigger). 17–25 tools advertised inline. |
| **Mass deferral** | `2.1.69` → `2.1.83` | 23 tools (Agent, Bash, Edit, Glob, Grep, Read, Skill, Write, …) moved to deferred. Inline `tool_count` collapses to **1** (just `ToolSearch`). System prompt grows to ~30K to hold the new "how to use ToolSearch" guidance. |
| **Hybrid** | `2.1.84` → present | 8 high-frequency tools (`Agent`/`Bash`/`Edit`/`Glob`/`Grep`/`Read`/`Skill`/`Write`) snap back to inline; everything else stays deferred. Settles at **9–10 advertised + 19 built-in deferred + ~89 MCP-deferred**. |

Net effect on the system prompt size: stable ~13K through 2025 → 16K at ToolSearch intro → 1.6K at the briefest moment (`2.1.4`, when only `ToolSearch` was inline) → 30K at peak (`2.1.83`, with full memory + ToolSearch instructions) → ~26K at the modern equilibrium.

## Key insights

### 1. The agent model converged late

The "agent" identity itself is younger than most of the tools. Until `2.1.53` (Feb 24, 2026) the system prompt called Claude Code an "interactive CLI tool"; from `2.1.53` it's an "interactive agent". The corresponding restructure (modern `# System` / `# Executing actions with care` blocks) is *more* of a concept change than any individual tool addition.

### 2. The deferred-tools system is a context-window optimization

Inline tool schemas are expensive — full advertisement of 25+ tools costs ~10–20K tokens of system prompt on every request. ToolSearch (`2.1.14`) and the mass deferral (`2.1.69`) move that cost from "per request" to "per first-use of a tool". The hybrid settled at `2.1.84` keeps the always-needed tools (`Bash`/`Read`/`Edit`/`Grep`/`Glob`/`Write`/`Agent`/`Skill`) inline so the common path is one round-trip and only rare tools pay the search cost.

### 3. Sub-agent vocabulary stabilized late

The tool name went `dispatch_agent` (`0.2.36`) → `Task` (`0.2.93`) → `Agent` (`2.1.63`) over ~12 months. The team-of-agents primitives (`TeamCreate`, `SendMessage`, `EnterWorktree`) all land in early 2026. Sub-agents existed from day one as a primitive but only became a first-class *system* with peer-to-peer messaging and worktree isolation in the `2.1.x` line.

### 4. MCP follows a documentation-then-activation playbook

`mcp_tool_count_advertised` is **always 0** across every captured version. MCP tools are *exclusively* deferred. Server tool *names* appeared in the user-prompt deferred block from `2.1.73` (March), but `mcp_tool_count_deferred` stayed `0` until `2.1.110` (Apr 15) — Anthropic shipped the prompt-side documentation 5 weeks ahead of the actual callability. This staged rollout suggests the team prioritizes prompt-stability for the model over fast-shipping new tools.

### 5. Skills are a 2026 phenomenon

The `Skill` *tool* shipped at `2.0.20` (Oct 16, 2025), three months before any actual skill metadata appeared in our captures (`2.1.23`, Jan 29, 2026). Once the catalog system landed, skills accreted quickly — by `2.1.108` Anthropic had a 6-skill bundle (`init`/`insights`/`review`/`security-review`/`statusline`/`team-onboarding`) shipping with the CLI itself, and even pruned 3 of those a day later. Skills are the live-wire surface where Anthropic's product experiments are most visible.

### 6. The autonomous-loop primitive matured in April 2026

A coordinated set of tools landed in a 3-week window: `Monitor` (`2.1.98`, Apr 9), `ScheduleWakeup` (`2.1.101`, Apr 10), `PushNotification` (`2.1.110`, Apr 15). Together they let the model self-pace ("wake me in 20 min", "ping me when this build event fires", "tell the user out-of-band when I'm done") — the building blocks for agents that run unattended for hours. The `loop` skill (`2.1.71`) and `schedule` skill (`2.1.83`) wrap them in user-friendly slash commands.

### 7. The system prompt is in budget pressure

System-prompt size oscillates wildly across the corpus:
- Sub-2K (`2.1.4`, briefly the only tool was `ToolSearch`).
- ~10–13K through 2025 (the comfortable equilibrium).
- 16K at `2.1.14` (when ToolSearch + MCP-server instructions both lived in the system prompt).
- 30K at `2.1.83` (Typed memory introduced; this is the all-time peak).
- ~26K at the modern equilibrium.

The repeated trim-and-revert pattern (`2.1.2`/`2.1.3`, `2.1.4`/`2.1.6`) is consistent with experimentation: ship a slimmed prompt, observe behavior degrade, roll back. The migration of MCP-server prose from system prompt (`2.1.14`) to user-prompt reminder (`2.1.110`) is the same pressure, more durably resolved.

### 8. Small changes can hide big concept shifts

The +8 tool diff at `2.1.84` looks small in the table — but it represents Anthropic walking back the most aggressive deferral experiment in the corpus, after roughly 3 weeks of "everything behind ToolSearch" (`2.1.69` → `2.1.83`). Reading the bullet list (`Agent`, `Bash`, `Edit`, `Glob`, `Grep`, `Read`, `Skill`, `Write`) as an *outcome* tells you what tools the model actually reaches for most often — they're the ones that earned an inline schema back.

## Caveats

- **The `04-with-skill` scenario** in our captures uses a deterministic fixture skill mounted into the sandbox. Skill counts in `manifest-stats.csv` reflect the baseline `02-bare` scenario, which has 0 skills until `2.1.23` and then tracks the Anthropic-shipped catalog only.
- **`mcp__claude_ai_*` and `mcp__plugin_*`** entries that briefly appeared in raw captures were the auth account's claude.ai-attached connectors, not Claude Code state — the repo now strips them at capture time. Treat any analysis predating the recapture sweep (May 4, 2026) as polluted.
- **`2.0.46`** shows an empty system prompt (146 lines deleted, 0 added). This is suspicious — likely a capture-time shape change (e.g., missing baseline scenario for that release) rather than an actual prompt regression. Worth a manual recapture if a future researcher cares about that specific window.
- **CLI-help diffs** (`01-cli-help` scenario) only capture *flag/command/argument identifiers*, not their descriptions. Wording-only changes won't show in `cli.csv`.
- **The mining script** parses bullet-list patterns from diff markdown, not raw `tools.json`/`skills.json`. A version that diff-versions.py couldn't render bullets for (because it had no predecessor — e.g. `0.2.36`, `1.0.4`) is missing from the per-event tables but present in `manifest-stats.csv`.
